# Design: Fix Author Metadata (issue #41)

## Problem

All 591 documents in `public/texts/` have `author: "Unknown"`. The app displays this
string verbatim in the document header for every matched text.

Root cause: the crawler (`crawl-bahai-library.cjs`) tries to extract the author from
`<meta name="author" content="...">` in the fetched xhtml, but the xhtml files use
`content` before `name` (`<meta content="..." name="author" />`). The regex only
matches the name-first form, so the meta tag is never found and every document falls
back to `'Unknown'`.

## Solution

Fix the meta tag regex to handle both attribute orderings, add a `CATEGORY_AUTHOR_LABELS`
map as a fallback for the authoritative-text categories (where the category itself
identifies the author), and run a one-time backfill to fix existing data.

## Category → Author Label Map

All 9 categories currently in the dataset:

| Category path | Author label | Docs |
|---|---|---|
| `/authoritative-texts/bahaullah/` | Bahá'u'lláh | 15 |
| `/authoritative-texts/the-bab/` | The Báb | 1 |
| `/authoritative-texts/abdul-baha/` | 'Abdu'l-Bahá | 14 |
| `/authoritative-texts/shoghi-effendi/` | Shoghi Effendi | 7 |

For `publications-individual-authors`, the meta tag fix (below) will extract the real
author (e.g. "J. E. Esslemont") when available. The category label is a last resort.

## Changes

### 1. Fix meta tag regex — `scripts/crawl-bahai-library.cjs`

Current regex only matches name-first attribute order:
```js
/<meta[^>]+name="author"[^>]+content="([^"]+)"/i
```

The xhtml files use content-first (`<meta content="J. E. Esslemont" name="author" />`).
Fix: try both orderings.

```js
function extractAuthorFromHtml(html) {
  const m = html.match(/<meta[^>]+name="author"[^>]+content="([^"]+)"/i)
           || html.match(/<meta[^>]+content="([^"]+)"[^>]+name="author"/i);
  return m ? m[1].trim() : null;
}
```

### 2. Add `CATEGORY_AUTHOR_LABELS` and use as fallback — `scripts/crawl-bahai-library.cjs`

Add the map near the top of the file. In the document-processing loop, change author
derivation to:

```js
author: extractAuthorFromHtml(html) || CATEGORY_AUTHOR_LABELS[doc.category] || 'Unknown'
```

### 3. Add `CATEGORY_AUTHOR_LABELS` and apply during rebuild — `scripts/rebuild-search-index.cjs`

Same map added to the rebuild script. When reading a text file, if `author === 'Unknown'`
and the document's `category` is known (read from the existing index metadata or passed
in), substitute the label. This ensures future rebuilds also produce correct authors
without re-crawling.

### 4. Backfill script — `scripts/backfill-authors.cjs` (new, one-time)

1. Load `public/search-index.json` → build `{docId: category}` map (category is already
   stored in index metadata).
2. Walk all `public/texts/*.json`. For each file:
   - Look up category from the map.
   - Derive correct author: `CATEGORY_AUTHOR_LABELS[category] || existing_author`.
   - If author changed, write the updated JSON back.
3. Mirror changed files to `assets/texts/` (keep both copies in sync).
4. Call `rebuild-search-index.cjs` to regenerate `public/search-index.json` and
   `assets/search-index.json` from the updated text files.

Note: for the one `publications-individual-authors` document, the backfill uses the
category label ("Individual Authors") since the xhtml is not re-fetched. A future
re-crawl will pick up the real meta-tag author ("J. E. Esslemont").

## Fallback Chain (after fix)

```
meta tag author (content- or name-first)
  → CATEGORY_AUTHOR_LABELS[category]
    → 'Unknown'
```
